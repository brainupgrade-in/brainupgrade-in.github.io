AI SRE Agents Compared: Azure, AWS, PagerDuty, Datadog

A practitioner’s breakdown of how Azure, AWS, PagerDuty, and Datadog handle autonomous SRE investigations in production environments.

Rajesh Gheware November 9, 2026

Key Takeaways

  • Azure offers configurable review vs autonomous modes with deep Microsoft ecosystem integration.
  • AWS DevOps Agent prioritizes deduplication and root cause analysis with manual mitigation approval.
  • PagerDuty’s Paige integrates directly into workflow channels like Slack and the Operations Console.
  • Datadog Bits Investigation provides evidence-backed conclusions for auto-investigated monitor alerts.
  • All four agents investigate actively rather than merely alerting, shifting the SRE workload.

The Shift from Alerting to Investigating

The landscape of Site Reliability Engineering is undergoing a structural shift. We are moving past the era where tools merely notify engineers of failures. The current standard, particularly as we look at the capabilities available in 2026, requires agents that actively investigate, correlate, and propose remediation. The four major players in this space—Microsoft Azure, Amazon AWS, PagerDuty, and Datadog—have each deployed distinct AI-driven SRE agents.

While the marketing around these tools often overlaps, the operational mechanics differ significantly. Understanding these differences is critical for architects designing enterprise platforms. You cannot simply plug these agents into a workflow and expect uniform results; their logic, integration points, and mitigation strategies are baked into their respective ecosystems.

Azure SRE Agent: Control Through Configuration

The Azure SRE Agent is designed for organizations deeply embedded in the Microsoft stack. It gathers context from Azure Monitor, Application Insights, and Log Analytics, while also pulling data from GitHub, Azure DevOps, and incident platforms like PagerDuty and ServiceNow.

The most critical differentiator for Azure is its explicit control over execution. As detailed in the official documentation, the agent operates in two distinct modes: Review and Autonomous. In Review mode, an SRE Agent Administrator must approve any write actions taken by the agent. This is crucial for financial institutions or regulated industries where change management is strict. In Autonomous mode, the agent acts and reports, but even here, tools can be set to allow, ask, or deny specific actions.

The agent extends via skills, custom agents, Python tools, MCP servers, and agent hooks. This extensibility allows enterprises to tailor the investigation logic to their specific infrastructure. If you are managing a hybrid environment where security compliance dictates human-in-the-loop approvals, the Azure SRE Agent provides the architectural guardrails to support that. AWS DevOps Agent: Deduplication and Root Cause

AWS approaches incident management through the lens of deduplication and structured investigation. The AWS DevOps Agent starts investigations from built-in integrations such as ServiceNow, webhooks (including PagerDuty or Grafana alarms), or manually.

A key feature of the AWS agent is its triage step. When a new incident arrives, the agent compares it against investigations active in a look-back window, typically 20 minutes. It then marks the incident as Linked (joined to an existing investigation), Skipped, or Proceed (starting a new investigation). This mechanism directly addresses the noise problem in large-scale distributed systems.

Once the investigation proceeds, the agent produces a root cause analysis and inline mitigation proposals. Crucially, a person reviews these proposals and chooses whether to apply them. Investigations can be escalated to AWS Support with the investigation log attached. This human-in-the-loop approach ensures that while the agent handles the heavy lifting of correlation and analysis, the final operational decision remains with the engineer.

PagerDuty’s Paige: Workflow Integration

PagerDuty’s SRE Agent, named Paige, takes a different approach by embedding itself directly into the communication and workflow layers. It runs in the Operations Console, on the incident details page, and in Slack. This placement is strategic; it meets responders where they already work.

Paige recommends diagnostic and remediation steps and can be added to an escalation level so it investigates in parallel with on-call responders. This "virtual responder" capability, currently in Early Access, allows the agent to gather context and suggest next steps while human engineers are still assessing the situation.

The strength of Paige lies in its ability to reduce the cognitive load on responders. By running in parallel, it ensures that background context is ready before the engineer needs to dive deep. This is particularly effective in high-pressure incidents where context switching is costly. Datadog Bits Investigation: Evidence-Backed Conclusions

Datadog’s Bits Investigation, formerly known as Bits AI SRE, positions itself as an autonomous agent for investigating production issues. It can auto-investigate when a monitor enters the alert state or be triggered manually from Slack using the command '@Datadog Investigate this alert'.

The output of a Bits Investigation is an evidence-backed or inconclusive conclusion, accompanied by suggested next steps. This format is useful for SREs who need to quickly understand the "why" behind an alert without manually correlating logs and metrics. The agent synthesizes data from Datadog’s monitoring suite to provide a narrative around the failure.

Unlike the Azure agent’s explicit mode-switching or AWS’s deduplication logic, Bits focuses on the clarity of the conclusion. It is designed to answer the question: "What happened?" rather than just "What is happening?" This makes it a strong complement to other tools in the stack, particularly for post-incident review and rapid triage.

Comparative Analysis: Which Agent Fits Your Stack?

Choosing between these agents depends on your existing infrastructure and your organizational culture regarding automation.

  • For Microsoft Shops: If your telemetry, CI/CD, and incident management are already in the Azure ecosystem, the Azure SRE Agent offers the deepest integration and the most granular control over execution modes.
  • For AWS-Centric Teams: If you rely on AWS native services and ServiceNow for ITSM, the AWS DevOps Agent’s deduplication logic and root cause analysis align well with existing workflows.
  • For Communication-Heavy Ops: If your team lives in Slack and the Operations Console, PagerDuty’s Paige provides the lowest friction for adopting AI assistance.
  • For Datadog Users: If your monitoring is centralized in Datadog, Bits Investigation provides a seamless way to turn alerts into actionable insights without leaving the platform.

Frequently Asked Questions

Q: Can these agents execute changes without human approval? A: Yes, but with constraints. The Azure SRE Agent can operate in Autonomous mode, but tools can be configured to allow, ask, or deny actions. The AWS DevOps Agent produces mitigation proposals that require a person to review and choose whether to apply them.

Q: How do these agents handle duplicate alerts? A: The AWS DevOps Agent explicitly compares new incidents with active investigations in a look-back window (typically 20 minutes) to mark them as Linked, Skipped, or Proceed. Other agents may handle correlation differently, but deduplication is a common feature.

Q: Do these agents only send alerts? A: No. All four agents—Azure SRE Agent, AWS DevOps Agent, PagerDuty’s Paige, and Datadog Bits Investigation—actively investigate issues. They gather context, analyze data, and provide conclusions or recommendations rather than merely notifying engineers.

Q: Where can I find official documentation for these agents? A: You should refer to the official vendor documentation for the most current details. For Azure, see the Azure SRE Agent Overview and Run Modes. For AWS, check the Production Operations Autonomous Incident Response guide. For PagerDuty, see the SRE Agent documentation. For Datadog, refer to Bits Investigation and Investigate Issues.
